`swap.getInstructions` builds the swap through Jupiter's Swap V2 `GET /swap/v2/build` instead of `POST /swap/v1/swap-instructions`. `/build` quotes the route again for the quote's input mint, output mint, `inAmount` and `slippageBps`, so the transaction metadata and action metadata carry the output amount `/build` returned. When a `/build` answer's `otherAmountThreshold` (the minimum output enforced on chain) is below the quote's but its `outAmount` still clears it, `/build` is asked once more with the slippage that keeps the quote's minimum; a swap whose minimum still falls short is refused with `BAD_REQUEST` and a message to refresh the quote. An answer that fails validation is refused with `JUPITER_ERROR`, as are one whose mints or `inAmount` differ from the quote, and one with non-empty `otherInstructions`. The lookup tables `/build` names are read from chain by key. `getInstructions` takes an optional `excludeDexes`, forwarded to `/build` when set, and refuses a built route through one of its labels with `JUPITER_ERROR`. `getQuote`'s `excludeDexes` does not carry into the built swap: callers that exclude DEXes send `excludeDexes` on `getInstructions` too. `getInstructions` refuses a quote whose `swapMode` is not `ExactIn`, or whose `otherAmountThreshold` is not a base-10 amount, with `BAD_REQUEST`. `useSharedAccounts`, `dynamicComputeUnitLimit` and `prioritizationFeeLamports` are accepted and ignored: `/build` takes no shared-accounts option, and the server sets the compute unit limit and price itself. `swap.getQuote` still quotes through `/swap/v1/quote`.
