`swap.getInstructions` builds the swap through Jupiter's Swap V2 `GET /swap/v2/build` instead of `POST /swap/v1/swap-instructions`. `/build` quotes the route again for the quote's input mint, output mint, `inAmount` and `slippageBps`, so the transaction metadata and action metadata carry the output amount `/build` returned. When a `/build` answer's `otherAmountThreshold` (the minimum output enforced on chain) is below the quote's but its `outAmount` still clears it, `/build` is asked once more with the slippage that keeps the quote's minimum; a swap whose minimum still falls short is refused with `BAD_REQUEST` and a message to refresh the quote. An answer that fails validation is refused with `JUPITER_ERROR`, as are one whose mints or `inAmount` differ from the quote, and one with non-empty `otherInstructions`. The lookup tables `/build` names are read from chain by key. `getInstructions` takes an optional `excludeDexes`, forwarded to `/build` when set, and refuses a built route through one of its labels with `JUPITER_ERROR`. Every `/build` request also excludes `JupiterRfqV2` (Jupiter RFQ v2, whose fills need a market maker's co-signature), merged with the caller's labels without duplicates, and a built route through it is refused with `JUPITER_ERROR`. The balance check counts rent for each associated token account the `/build` setup instructions create with the taker as payer and that does not exist yet (the output account, also when `destinationTokenAccount` is set, intermediate accounts of a multi-hop route, and the wrapped SOL account of a SOL input), sized by its token program: 165 bytes for SPL Token, and for Token-2022 the account extensions the mint requires plus ImmutableOwner. `getQuote`'s `excludeDexes` does not carry into the built swap: callers that exclude DEXes send `excludeDexes` on `getInstructions` too. `getInstructions` refuses a quote whose `swapMode` is not `ExactIn`, or whose `otherAmountThreshold` is not a base-10 amount, with `BAD_REQUEST`. `useSharedAccounts`, `dynamicComputeUnitLimit` and `prioritizationFeeLamports` are accepted and ignored: `/build` takes no shared-accounts option, and the server sets the compute unit limit and price itself. `swap.getQuote` quotes through `/build` too, for a placeholder taker, instead of Metis `GET /swap/v1/quote`, and returns only the quote fields: `inputMint`, `inAmount`, `outputMint`, `outAmount`, `otherAmountThreshold`, `swapMode`, `slippageBps`, `priceImpactPct` and `routePlan`. It no longer sends `excludeRouters=jupiterz`; it excludes `JupiterRfqV2` on top of the caller's `excludeDexes` instead. It refuses an `ExactOut` quote with `BAD_REQUEST`, because `/build` swaps an exact input only. A `/build` answer of `{"error":"No routes found"}` with HTTP 400 comes back as `BAD_REQUEST` from both procedures, not `JUPITER_ERROR`.
