The tokens-to-rent service prices and builds its swaps through Jupiter's Swap V2 `GET /swap/v2/build` instead of `/v1/quote` and `POST /swap/v1/swap-instructions`, and no longer depends on `@jup-ag/api`. `JUPITER_URL` is replaced by `JUPITER_API_URL`, the API's base URL, which defaults to `https://api.jup.ag`; `JUPITER_API_KEY` is sent as `x-api-key`. The platform fee settings `JUPITER_FEE_BPS` and `JUPITER_FEE_ACCOUNT` are removed. The fee-funding swap is bounded with `maxAccounts=20` and `maxBytes=950`, a budget that aims to keep the transaction under 1232 bytes (an estimate from measured routes), in place of `onlyDirectRoutes`, which `/build` does not take. Every request excludes Jupiter RFQ v2. A `/build` answer that fails validation, swaps other mints or another amount than requested, routes through RFQ v2, or carries `otherInstructions` is refused. The transaction's compute unit limit is 20% over the units it uses in simulation, and a request whose transaction fails simulation is refused. The transaction drops the unit price `/build` returns, so the user repays the flat 10000 lamports as before. A `/fees` build whose setup creates a token account besides the user's wrapped SOL account is refused, since the loan covers the rent of that one account. The package gains a `test` script for its unit tests.
