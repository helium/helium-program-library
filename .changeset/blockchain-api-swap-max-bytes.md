`swap.getInstructions` measures the serialized swap transaction, signature slots included, against Solana's 1232-byte packet limit. A Jupiter route can serialize over it once the compute budget instructions are added; such a transaction was returned unsendable or failed as an internal error. A transaction over the limit is now built again through Jupiter's `/swap/v2/build` with a `maxBytes` of the bare swap's estimated size lowered by the overshoot, up to 3 times, and each requote still has to clear the quote's minimum output. The estimate is the size of a v0 transaction of Jupiter's instructions and lookup tables alone, so when Jupiter counts the bare swap the same way and has a route within that `maxBytes`, the first requote fits. Each later requote is capped at the previous `maxBytes`, and a requote whose transaction is no smaller than the one before it lowers the next `maxBytes` by the overshoot plus twice the previous step. Steps of 1, 3 and 7 times the overshoot add up to 11 times it, so a route Jupiter counts up to 10 times the overshoot below the estimate is replaced by a fitting one within the 3 requotes, when Jupiter has a route within each requote's `maxBytes`; a grown step can pass below the only routes that fit, and that requote is refused. A route that stays over the limit, a requote Jupiter finds no route for within its `maxBytes`, or a requote whose routes fall below the quote's minimum output is refused with the new `TRANSACTION_TOO_LARGE` error (HTTP 422). The first build sends no `maxBytes`, so a route that fits is unchanged, and its minimum-output refusal stays an expired quote. `/build` is requested at most 8 times per call: 4 builds, each with the existing one-retry minimum-output check.
